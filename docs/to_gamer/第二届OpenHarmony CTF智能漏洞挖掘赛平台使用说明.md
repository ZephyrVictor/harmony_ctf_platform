# 第二届OpenHarmony CTF智能漏洞挖掘赛平台使用说明

## 一、说明范围

本文档面向第二届 OpenHarmony CTF 智能漏洞挖掘赛参赛队伍，说明比赛平台的基本操作、Nday 题目提交规范、0day 提交流程、计分规则，以及通过后端 API 与预置 Agent Skill 参与比赛的标准方式。

比赛平台地址：

```text
https://thuctf.tsinghua.edu.cn/harmonyctf/
```

参赛队伍应使用本人或本队授权账号登录平台，并遵守赛事规则、平台提示和组委会发布的补充说明。未经授权不得对比赛平台、后台服务或非赛题目标进行扫描、攻击、干扰或批量请求。

## 二、平台基本操作流程

### 2.1 登录与组队

1. 访问比赛平台地址。
2. 使用参赛账号登录。
3. 在队伍页面创建队伍或加入已有队伍。
4. 确认队伍名称、队伍成员和参赛状态正确。
5. 进入比赛页面，阅读比赛说明、承诺书、题目规则和 0day 提交要求。

参赛队伍应确保同一队伍内的账号、提交记录和 0day 工单归属清晰。不得借用他人账号提交，不得通过多个队伍重复提交同一成果。

### 2.2 加入比赛

1. 在比赛列表中选择“第二届 OpenHarmony CTF 智能漏洞挖掘赛”。
2. 按页面提示完成参赛确认。
3. 如果比赛设置了队伍审核、邀请码或赛区选择，按页面要求完成相应操作。
4. 成功进入比赛首页后，可查看题目列表、排行榜、提交记录、通知和 0day 提交说明。

### 2.3 题目页面

题目列表展示每道题目的名称、分类、总分和解题状态。题目可能包含多个漏洞 Track，每个 Track 对应一条独立漏洞链。每条漏洞链通常由 Level 1、Level 2、Level 3 三个阶段组成。

题卡显示的分数表示该题在当前配置下的可获得总分。若一道题包含多个 Track，则题目总分可能大于单条漏洞链的分数。队伍实际得分以每个 Track、每个 Level 的 Accepted 提交记录为准，不会因为完成题目而额外重复加一次题目总分。

## 三、Nday 题目提交规范

### 3.1 基本原则

Nday 题目按漏洞链逐级提交。推荐按以下顺序完成：

1. Level 1：提交漏洞位置，确定一条漏洞 Track。
2. Level 2：在同一 Track 下提交对应 commit hash。
3. Level 3：在同一 Track 下提交对应 CWE 分类。

Level 1 提交成功后，平台会确定对应的 Track。使用网页前端时，平台会在题目弹窗中维护当前 Track 状态；使用后端 API 或 Agent Skill 时，必须保存 Level 1 返回的 `trackId`，并在提交 Level 2、Level 3 时携带同一个 `trackId`。

如果同一道题中发现另一条漏洞链，应重新提交 Level 1 来开始新的 Track，不应复用旧 Track 的 `trackId`。

### 3.2 Level 1：漏洞位置提交

Level 1 用于提交漏洞所在的源代码位置。标准格式为：

```text
文件路径:行号
```

示例：

```text
foundation/communication/netmanager_base/services/netmanagernative/src/netsys/net_manager_native.cpp:128
```

Level 1 的判定以数据集中的文件路径和行号范围为准。参赛队伍通常只需提交一个单行号；只要该行号位于数据集标注的漏洞范围内，即可命中并获得该 Level 分数。例如，若数据集标注范围为 `120-135`，提交 `128` 可以命中；提交超出范围的行号不会命中。

如题目或官方说明明确要求提交范围，也可使用范围格式：

```text
文件路径:120-128
```

提交范围必须落在数据集标注范围内。过宽的范围可能因为超出标注范围而判定失败。为降低格式错误风险，建议优先提交最能代表漏洞点的单行号。

Level 1 提交注意事项：

- 文件路径应使用题目或源码仓库中的相对路径。
- 路径分隔符建议统一使用 `/`。
- 行号必须为正整数。
- 不要在答案中附加解释性文字、Markdown、URL 或代码片段。
- 已提交过的level不会重复计分，应继续提交同一 Track 的下一 Level。

> 例如对于一个模块，有patha:128 commithash:114514 CWE-78, 和 pathb:128 commithash:114512 CWE-787。我们可能存在先提交patha:128, 获得这一level的分数，然后后面暂时没有找到，转而提交pathb:128, 获得这一level的分数。 后续如果想要继续提交patha，则应先提交patha:128，此时不会计分，然后接着提交对应的commit hash和cwe。

### 3.3 Level 2：commit hash 提交

Level 2 用于提交该漏洞链对应的 commit hash。标准格式为纯 commit hash：

```text
5fc8a01873867354a83a69b6d9275fa53c78be6a
```

Level 2 提交注意事项：

- 以题目配置和赛事数据集要求的 commit 为准。
- 通常应提交完整 hash；如页面或官方说明允许短 hash，再按说明提交。
- 不要提交 commit URL、PR 链接、说明文字或多余空格。
- Level 2 必须对应 Level 1 已命中的同一 Track。
- 使用 API 或 Agent Skill 时，必须携带 Level 1 返回的 `trackId`。

### 3.4 Level 3：CWE 分类提交

Level 3 用于提交该漏洞链对应的 CWE 分类。推荐使用标准 CWE 编号格式：

```text
CWE-787
```

Level 3 提交注意事项：

- 以题目配置和赛事数据集要求的 CWE 为准。
- `CWE` 应当大写，同时编号必须为整数。
- 不要提交漏洞名称、自然语言解释或多个候选项，除非题目明确要求。
- Level 3 必须对应同一 Track，并在 Level 2 通过后提交。
- 使用 API 或 Agent Skill 时，必须携带同一个 `trackId`。

### 3.5 多 Track 提交

同一道题可能包含多条独立漏洞链。每条漏洞链独立计分，提交顺序建议为：

```text
Track A: Level 1 -> Level 2 -> Level 3
Track B: Level 1 -> Level 2 -> Level 3
Track C: Level 1 -> Level 2 -> Level 3
```

也可以先提交多个 Level 1，再逐条补充后续 Level，但参赛队伍必须明确每个 Level 2、Level 3 对应哪个 Track。网页前端会展示 Track 状态；后端 API 和 Agent Skill 使用者应自行记录 `trackId` 与漏洞位置的对应关系。

## 四、计分、重复提交、冷却与封禁

### 4.1 计分规则

Nday 分数按 Level 逐项入账。每个 Track 的总分为该 Track 启用 Level 分值之和。例如默认配置下：

```text
Level 1 = 5 分
Level 2 = 4 分
Level 3 = 1 分
单条 Track 满分 = 10 分
```

如果一道题包含多个 Track，题卡显示的题目总分会按 Track 数量累计。例如一题包含 3 条 Track，且每条 Track 为 `5 + 4 + 1`，则该题可获得总分为 30 分。

队伍总分由已通过的 Level 提交记录、管理员明确调分和 0day 加分组成。错误提交默认不扣分；是否存在特殊扣分、封禁或冷却，以比赛页面和组委会规则为准。

### 4.2 重复提交

同一队伍对同一 Track、同一 Level 已经 Accepted 后，再次提交相同或等价答案不会重复得分。平台可能提示“已提交”或引导继续提交下一 Level。

### 4.3 错误提交与冷却

平台设置了错误提交冷却机制。错误提交达到阈值后，该题会进入冷却状态，冷却期间不能继续提交该题答案。页面会展示冷却提示和剩余时间。

参赛队伍应避免无依据的枚举、爆破和批量尝试。若进入冷却，应等待冷却结束后再提交经过确认的答案。正确提交通过后，相关错误计数会按平台规则恢复。

### 4.4 Trap 与封禁

部分题目可能配置 Trap 答案。提交 Trap 答案可能导致当前 Track、当前 Level 被封禁，或触发题目级临时锁定。封禁后继续提交该 Track、该 Level 不会得分。

参赛队伍不得尝试枚举 Trap 答案，不得通过自动化方式大规模试探答案空间。若页面提示封禁或锁定，应停止相关提交，并根据比赛规则联系管理员或等待处理。

## 五、0day 提交规范

### 5.1 0day 提交门槛

比赛可能要求队伍达到一定 Nday 分数后，才允许提交 0day 工单。平台会在 0day 页面显示当前 Nday 得分、所需门槛以及是否允许提交。

若按钮不可用或页面提示未达到门槛，说明当前队伍暂不满足 0day 提交条件。参赛队伍应先继续完成 Nday 题目，不应尝试绕过前端或后端校验。

### 5.2 0day 工单内容

提交 0day 工单时，应尽量完整填写以下信息：

| 字段 | 说明 |
| --- | --- |
| 标题 | 简明描述漏洞对象、漏洞类型和影响范围 |
| 描述 | 说明漏洞成因、触发条件、影响结果和复现思路 |
| 严重程度 | 按平台选项选择 None、Low、Medium、High 或 Critical |
| 模块/子模块 | 漏洞所属 OpenHarmony 模块或子模块 |
| 文件路径 | 漏洞相关源文件路径 |
| 行号或范围 | 如 `c:128`、`c:120-135` |
| commit hash | 与漏洞修复、引入或研判相关的 commit hash，以赛事要求为准 |
| CWE | 标准 CWE 编号，如 `CWE-787` |
| PoC / 佐证 | 复现步骤、输入样例、分析证据或可验证说明 |

0day 工单应保证信息真实、可复核、可定位。不要提交与赛题无关的内容，不要提交无法复现的泛泛描述，不要在工单中夹带账号密码、私钥、平台 Cookie 或其他敏感信息。

### 5.3 审核与加分

0day 工单提交后由管理员审核。审核结果可能为通过或驳回。通过后，管理员可依据赛事规则给予 0day 加分；相关分数变化会进入排行榜和分数记录，并通过平台通知展示。

## 六、后端 API 与 Agent Skill 使用

### 6.1 使用场景

参赛队伍可以通过网页前端完成全部比赛操作。若需要在 Agent、脚本或自动化辅助环境中查询题目状态、提交答案或提交 0day 工单，推荐使用赛事预置的公开 Skill， 也可自行分析后端并对自己的Agent系统做更加定制的适配。

预置 Skill 路径：

```text
to_gamer/skills/openharmonyctf-platformskill/
```

打包文件路径：

```text
to_gamer/skills/skill.tar.gz
```

该 Skill 面向参赛者使用，提供登录、列出比赛、选择比赛、创建或加入队伍、加入比赛、查看题目、提交 Level 1/2/3 答案、查询提交状态、创建和查询 0day 工单等能力。


## 七、Agent 使用规范

使用 Agent 参与比赛时，参赛队伍仍对所有提交行为负责。建议向 Agent 明确以下约束：

1. 先确认平台地址、登录状态和当前账号。
2. 先列出可见比赛，不得自动选择比赛。
3. 选择比赛、创建队伍、加入比赛、提交答案、提交 0day 工单前，应由参赛者确认。
4. 每次提交前先查询题目状态，检查 Track、Level、冷却、锁定和封禁状态。
5. Level 1 不携带 `trackId`；Level 2、Level 3 必须使用同一 Track 的 `trackId`。
6. 不得爆破答案、枚举 Trap、绕过 0day 门槛或绕过平台风控。
7. 不得在提示词、日志、仓库或工单中泄露密码、Cookie、私钥、访问令牌等敏感信息。

推荐 Agent 指令示例：

```text
请使用 openharmonyctf-platformskill 参与比赛。先检查登录状态，列出可见比赛，等待我选择比赛；之后查看题目状态。每次提交答案前先向我确认，Level 1 不携带 trackId，Level 2/3 使用对应 Level 1 返回的 trackId。提交 0day 工单前先检查 canSubmitZeroDay 和当前 Nday 分数。
```

## 八、参赛合规要求

参赛队伍应遵守以下要求：

- 仅对比赛授权范围内的题目、源码和目标进行分析。
- 不得攻击比赛平台、后台服务、数据库、排行榜、其他队伍账号或非授权系统。
- 不得通过爆破、撞库、批量枚举、绕过鉴权等方式获取答案或破坏比赛秩序。
- 不得共享账号、Cookie、队伍邀请码或未公开题目信息。
- 不得提交伪造、不可复核、与题目无关或侵犯第三方权益的 0day 工单。
- 若发现平台异常、计分异常、敏感信息泄露或可影响比赛公平性的漏洞，应及时联系组委会。

## 九、常见问题

### 9.1 为什么提交单行号可以通过 Level 1？

Level 1 以数据集标注的漏洞位置范围为判定依据。若数据集答案为一个范围，参赛队伍提交该范围内的单个有效行号即可命中。建议提交最具代表性的漏洞触发行或关键语句行。

### 9.2 为什么题卡显示分数大于 10 分？

题卡显示的是该题全部 Track 的可获得总分，不是单条漏洞链的分数。若题目包含多条漏洞链，每条漏洞链均可按 Level 得分累计。

### 9.3 答错是否默认扣分？

默认情况下，导入的多 Level Nday 题目错误提交不扣分。但错误提交会计入冷却机制，达到阈值后需要等待冷却结束。具体规则以比赛页面和组委会公告为准。

### 9.4 0day 页面无法提交怎么办？

先查看页面显示的当前 Nday 分数和所需门槛。未达到门槛时，平台会禁用 0day 提交入口。达到门槛后刷新页面或重新进入 0day 页面即可继续提交。

### 9.5 API 提交 Level 2 或 Level 3 总是失败怎么办？

检查是否使用了 Level 1 返回的正确 `trackId`。Level 2、Level 3 必须延续同一条漏洞链；若缺少 `trackId` 或使用了另一条 Track 的 `trackId`，提交会失败或无法得分。
