### 3.8 题目冷却（新特性）

> 需先执行冷却实现计划，再测本节

#### 3.8.1 后端 API 验证
```bash
# Admin 设 CooldownMinutes=1（快速测试）
curl -X PUT http://10.77.0.10:8081/api/edit/Games/1 -b /tmp/admin_cookies.txt \
  -H 'Content-Type: application/json' -d '{...,"cooldownMinutes":1}'

# 查询 trackCount（challenge 1 有 12 track → limit=60）
curl -s http://10.77.0.10:8081/api/ext/challenges/1/tracks -b /tmp/admin_cookies.txt | jq 'length'
# 期望 12

# 答错 59 次（不冷却）
for i in $(seq 1 59); do
  curl -s -X POST http://10.77.0.10:8081/api/game/1/Challenges/1 -b /tmp/pa_cookies.txt \
    -H 'Content-Type: application/json' -d "{\"flag\":\"wrong_$i\"}" > /dev/null
done
# 查冷却状态
curl -s http://10.77.0.10:8081/api/game/1/Challenges/1 -b /tmp/pa_cookies.txt | jq '.cooldown'
# 期望 wrongCount=59, cooldownUntil=null

# 答错第 60 次（触发冷却）
curl -s -X POST http://10.77.0.10:8081/api/game/1/Challenges/1 -b /tmp/pa_cookies.txt \
```

## 7. 测试执行流程

### 7.1 每个 feature 的执行顺序
```
1. 后端 curl 验证（API 层）
   ↓ 全部通过
2. 前端 Puppeteer e2e（UI 层）
   ↓ 发现问题
3. 记 issue 到 docs/test-issues-iteration2.md
   ↓
4. 修复
   ↓
5. 重跑该 feature 全部测试用例（回归）
   ↓ 通过
6. 标记 issue 已修复
```

### 7.2 截图规范
- 命名：`<feature>-<场景>-<步骤>.png`（如 `F3-manual-modal.png`）
- 全页截图（`fullPage: true`）
- 关键步骤必截：弹窗、toast、错误状态、最终结果

### 7.3 Trace 记录
- Puppeteer 启动时开 trace：`page.tracing.start({path: 'trace.json'})`
- 关键场景结束停止：`page.tracing.stop()`
- trace 存：`trace-shots/iter2/<feature>/trace/`
